## 2. 数据集组成

### 2.1 按主题组织

选 10 个主题，每个主题约 20 个文件，几种文件类型都有。按主题组织有两个用处：

- **混合型查询需要它。** 同一主题里既有文字文档，又有没有字的图片，才写得出“既要靠文字、又要靠画面”的查询。
- **视觉型查询需要干扰项。** 同一主题里有多张相似的图片（比如几张不同的狗），CLIP 才不是在“猫狗二选一”，指标才有区分度。

主题示例（可以换，但要定下来再收集）：

| 主题 | 文字文档举例 | 图片举例 |
|---|---|---|
| 校园生活 | 学院公开通知、校历 | 教学楼、食堂、操场 |
| 交通出行 | 交通法规、列车时刻表 | 公交车、地铁站、自行车 |
| 饮食 | 菜谱、食物营养成分表 | 各种菜品、水果 |
| 动植物 | 科普文章 | 猫、狗、鸟、花草 |
| 体育运动 | 比赛规则、赛程表 | 篮球场、跑步、球类 |
| 天气与自然 | 气象公报 | 雪景、日落、雨天街道 |
| 电子产品 | 产品说明书、参数表 | 手机、耳机、键盘 |
| 办公与财务 | 报销制度、预算表 | 文具、会议室 |
| 建筑与旅游 | 景点介绍 | 古建筑、桥、街景 |
| 健康 | 健康科普 | 运动器材、药盒外观（不拍说明书文字） |

### 2.2 文件配额（按 D1 的 200 个）

| `type` | 数量 | 来源举例 | 在系统里靠什么被检索到 |
|---|---|---|---|
| `pdf` | 50 | 政府公开文件、维基百科条目导出的 PDF | 正文 BM25 |
| `scanned_pdf` | 20（合计不少于 40 页） | 把公开文件打印出来再扫描；公开档案的扫描件 | OCR |
| `docx` | 40 | 政府公开文件（`.doc` 另存为 `.docx`）、自制文档 | 正文 BM25 |
| `xlsx` | 20 | 统计数据表、自制表格 | 正文 BM25 |
| `image`（有字） | 30 | 海报、路牌、课件照片、网页截图 | OCR + CLIP |
| `image`（无字） | 40 | 自己拍的照片 | 只有 CLIP |

`manifest.csv` 的 `type` 只有 `image` 一种，有字、无字写在 `notes` 列（写“有字”或“无字”），再写主题，例如 `无字; 动植物`。

### 2.3 来源与版权

- `source` 必填，格式统一为“来源; 网址或说明; 许可”，例如：
  - `中国政府网; https://www.gov.cn/…; 国家机关公文，不受著作权保护（著作权法第五条）`
  - `维基百科; 条目“大熊猫”; CC BY-SA 4.0`
  - `自己拍摄; 2026-12-01 校园`
  - `自制; 模拟的部门预算表`
- 优先选不受著作权保护或开放许可的内容。原文件放在 `experiments/datasets/files/`，这个目录已在 `.gitignore` 里，不进 Git。
- 自制文件在论文里要说明是自制的，比例尽量小。

### 2.4 收集文件时的规则（会直接影响实验结果）

1. **文件名保持原样。** 下载的文件用网站给的名字，照片用手机生成的名字（如 `IMG_4031.jpg`），不要为了好找而改名。B0 只查文件名（D2），改名会直接抬高 B0。
2. **格式。** 系统按文件内容判断类型，只接受 PDF、DOCX、XLSX、PNG、JPG（`.env.example` 的 `UPLOAD_ALLOWED_TYPES`）。`.doc`、`.xls` 先另存为新格式，在 `notes` 里写“由 .doc 另存”。iPhone 拍的照片默认是 HEIC，要导出成 JPG（或者把相机格式设成“兼容性最佳”再拍）。
3. **大小。** 单个文件不超过 50 MB（`UPLOAD_MAX_BYTES`）。
4. **隐私。** 照片里不出现别人的正脸、证件号、电话、学号、真实票据；自制文件里不写真实的个人信息。论文截图也照这条来。
5. **扫描件要真的没有文本层。** 有的扫描 App 会自动加一层文字，系统会把它当普通 PDF，不走 OCR。导入处理后要检查一遍（§6 第三周第 4 步），不符合的改 `type` 或换文件。
6. **不收内容完全相同的文件。** 两份相同的文件会变成两个 `file_id`，标注时要判两遍，还会影响 BM25 的统计。

## 3. 查询集

### 3.1 数量

| 类型 | 条数 | 要求 |
|---|---|---|
| `text` 文字型 | 30 | 其中至少 10 条要找的内容只在 OCR 文字里（扫描件或有字图片），否则 B1 和 B2 比不出差别 |
| `visual` 视觉型 | 25 | 相关文件都是图片 |
| `mixed` 混合型 | 20 | 见下面的定义 |

编号建议用 `t001`–`t030`、`v001`–`v025`、`m001`–`m020`，一眼能看出类型。

### 3.2 三类怎么判定

- **文字型：** 要找的信息以文字形式出现在正文或 OCR 文字里。
- **视觉型：** 相关文件都是图片，并且图片的 OCR 文字里没有查询的关键内容。判定方法：在系统里打开每张相关图片的“抽取文本”标签页（T24f）看一眼，OCR 文字里有查询的关键内容，就改成混合型。
- **混合型：** 相关文件里既有靠文字才能找到的文档，也有只能靠画面找到的图片；或者一张图片要同时靠图中文字和画面才算相关。例如“学校运动会的通知和照片”。

注意：只有单独上传的图片有 CLIP 向量。扫描 PDF 的页面、文档里的插图都没有（文档内嵌图片的抽取是 P4），所以视觉型查询的相关文件只能是图片文件。

### 3.3 写查询的规则

1. **先写查询，后看系统结果。** 写好的查询不因为系统答得不好就删掉或改写（GLOBAL §9.2 第 8 条）。真写错了（错别字、类型判错）可以改，在查询备注里记下原因。
2. **像真实用户那样写。** 关键词式（“列车 时刻表”）和短句式（“周末去北京的火车几点发车”）都要有，长度大致 2–20 个字。
3. **用自己的话说。** 不整句照抄原文，可以带原文里的关键词。整句照抄对 BM25 太容易。
4. **视觉型查询要具体到能区分同主题的图片。** 写“草地上的黑狗”，不写“狗”；不然同主题的图片全部相关，指标没有区分度。
5. **以中文为主。** DocVQA 不并入正式数据集，只作流程验证。

### 3.4 查询备注（程序不读）

`experiments/annotation/query_notes.tsv`：`query_id`、写查询时参照的文件、要找的内容在哪里（`body` / `ocr` / `visual`）、修改记录。这个目录不在 `qrels/` 下，`validate` 不读它（`dataset.py` 只读 `qrels/*.tsv`），但它进 Git，论文分析失败案例时用得上。

## 4. 相关性标注

### 4.1 等级

沿用 Barry 于 2026-11-19 确认的 0–3 级（`experiments/README.md` 第 2 节）。代码里的计算方式（`metrics.py`）：

- P@K、R@K 把等级大于 0 的都算“相关”，所以 **1（部分相关）也会算进 P@K**。只有文件确实提到了查询的内容才标 1，拿不准就标 0。
- nDCG 的增益是 2^等级 − 1，3 级的分量是 1 级的 7 倍。

### 4.2 分三步标

**第一步：已知项。** 写查询时参照的那个文件直接标 3，写进 `qrels/known_items.tsv`。这一步和写查询同时做，不需要运行系统。

**第二步：候选池（pooling，TREC 的常用做法）。** 代码冻结后在 Windows 上把 10 个配置各跑一次（qrels 里只有已知项也能跑：没有相关文件的查询只是不进平均，`runner.py` 照常保存排名），把每条查询在每个配置里的前 20 名合在一起，去掉已经判过的，得到待判列表，逐条判 0–3，写进 `qrels/pool.tsv`。

- 深度取 20，是因为实验算到 @20（所有配置都是 `top_k: 20`、`ks: [5, 10, 20]`）。池子浅于 20，@20 的指标里就会混进没判过的文件。
- 判完再用 T25a 的检查功能确认：10 个配置前 20 名里没判过的为 0。

**第三步：按主题补判图片。** 视觉型和混合型查询，把查询所在主题的全部图片（每个主题约 7 张）也判一遍。CLIP 和 OCR 都没找到的相关图片，候选池里不会有，不补的话 R@K 会偏高。

**工作量估计：** 75 条查询 × 每条约 30 个候选 ≈ 2,000–2,500 对，加上补判的约 300 对。按每对 5–10 秒算，大约 4–7 小时，分三四个晚上做。这是估计，第一晚判完可以按实际速度重算。

### 4.3 判的时候

- 打开原文件看（`experiments/datasets/files/` 下，或在系统预览页看 PDF 原页和“抽取文本”）。
- **盲判：** 待判列表只有查询和文件，不写是哪个配置找到的、排第几（T25a 按 `query_id`、`file_id` 排序输出），避免不自觉地偏向某个方案。

### 4.4 自我一致性检查

全部判完一周后，随机抽 10%（约 200 对），不看原来的等级重判一遍，按“相关 / 不相关”两类算一致率，写进 README。只有一个人标注，这一点写进论文的局限；有余力的话找一位同学独立判 10 条查询作对照。

## 8. T25a：候选池工具（D3，批准后另做，一个任务一个 commit）

```
python -m app.modules.experiments pool --runs <结果目录>... [--depth 20] --out <待判列表>
python -m app.modules.experiments pool --runs <结果目录>... [--depth 20] --check
```

- **输入：** `runs/` 下若干结果目录的 `results.jsonl`。每个名次已经带 `file_id`（`runner.py` 写入），不需要连数据库。
- **输出：** 待判列表，列为 `query_id`、查询文本、查询类型、`file_id`、文件路径、等级（空着）。按 `query_id`、`file_id` 排序，不带名次和配置名（盲判）；已经在 `qrels/` 里判过的不再列出。
- **`--check`：** 只报告这些运行的前 N 名里还有多少对没判过。冻结前要求为 0；T26 跑完再查一次。
- **填好之后：** 再提供一步把填好的列表转成 `qrels/pool.tsv`，检查每行都填了 0–3。用 WPS 或 Excel 编辑 TSV，另存时可能改掉编码或分隔符；具体用 TSV 还是 CSV，在 T25a 的计划里定。
- **测试：** 纯文件读写，`backend` 单元测试在 Mac 上就能完整跑。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 标注量比估计的大 | 先保住下限：每类至少 20 条查询（共 60 条）；按第一晚的实际速度重新估算 |
| 候选池偏差：系统都没找到的相关文件会漏标，R@K 偏高 | 图片按主题补判；文字文档的漏标写进论文局限 |
| 系统、查询、标注都出自同一个人 | 先写查询后看结果；失败的查询不删；这些规则写进论文的实验设计 |
| 只有 Windows 机器能跑实验 | 第三周要连续占用那台机器，提前排好 |
| 数据集偏向某个通道 | 有字图片 30 张，OCR 和 CLIP 都有机会；文字型查询里至少 10 条只靠 OCR |
