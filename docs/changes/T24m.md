## 1. 问题

`27b51b2` 把 `pdfjs-dist` 里的 CMap、标准字体、WASM、ICC 共 202 个文件手工复制到 `frontend/public/pdfjs/`。以后升级 `pdfjs-dist` 时如果忘了重新复制，新版本的 pdf.js 会读到旧版本的资源（尤其是 WASM 解码器），可能出错，也可能像这次一样中文 PDF 显示空白，而且没有任何测试能发现。

## 2. 逐文件修改记录

| 文件 | 修改 | 原因 |
|---|---|---|
| `frontend/scripts/pdfjs-assets.mjs`（新增） | `ASSET_DIRS`（与 `PdfViewer.vue` 的四个资源地址对应）、`hashFiles()`（递归算 sha256）、`diffAssets()`（缺少、多余、内容不同）、`pdfjsVersion()` | 测试和复制脚本共用 |
| `frontend/scripts/sync-pdfjs.mjs`（新增） | 四个目录先删后复制，再用 `diffAssets` 复核；源目录不存在时提示先 `npm install`，退出码 1 | 先删后复制，旧版本多出的文件不会残留 |
| `frontend/tests/pdfjs-assets.test.mjs`（新增，3 项） | 四个目录与已安装的 pdfjs-dist 逐文件一致；每个目录非空；比较逻辑能发现三种差异（临时目录） | 失败信息里写明“运行 npm run sync:pdfjs” |
| `frontend/package.json` | 新增脚本 `sync:pdfjs` | — |
| `frontend/README.md` | 常用命令加 `npm run sync:pdfjs`（升级 pdfjs-dist 后必须运行）；目录说明加 `scripts/`、`public/pdfjs/` | — |

**为什么写成 `.mjs`。** 项目没有装 `@types/node`，而 `vue-tsc` 会检查 `tests/` 下的 `.ts`；这里要用 `node:fs`、`node:crypto`。写成 `.mjs` 不进类型检查，vitest 照样收集，不需要新依赖。
