## 1. 问题

T24a 让 Worker 启动时先连一次数据库，连不上就以退出码 1 结束。但连接没有超时：数据库主机不可达（不是端口没开，而是包被丢掉）时，要等操作系统的 TCP 超时才报错。本机实测 75 秒。

------------------------------------------------------------------------

## 2. 逐文件修改记录

| 文件 | 修改 | 原因 |
|---|---|---|
| `shared/task_queue.py` | 新增 `connect_kwargs(timeout)`：`None` 返回 `{}`，否则 `{"connect_timeout": timeout}`；`PgTaskQueue.__init__` 新增关键字参数 `connect_timeout_seconds: int \| None = None`，`_connection()` 把它传给 `psycopg.connect` | 默认 `None`，其他调用方行为不变；关键字参数会覆盖连接串里同名的设置 |
| `services/ocr_worker/ocr_worker/store.py` | `PgStore.__init__` 新增同名参数，连接时用同一个 `connect_kwargs` | OCR Worker 的启动检查用的是 `store.ping()`，两个连接都要有超时 |
| `backend/app/config.py` | 新增 `worker_db_connect_timeout_seconds: int = 10`（2–300） | libpq 的 `connect_timeout` 只接受整数，小于 2 时按 2 处理，所以配置里直接拒绝 1 |
| `services/ocr_worker/ocr_worker/config.py` | 新增 `ocr_worker_db_connect_timeout_seconds: int = 10`（2–300） | 同上 |
| `backend/app/worker/__main__.py` | 创建 `PgTaskQueue` 时传入配置值 | — |
| `services/ocr_worker/ocr_worker/__main__.py` | 创建 `PgTaskQueue`、`PgStore` 时传入配置值 | — |
| `.env.example` | 两个配置项各加一行说明 | GLOBAL §11.2 |

## 5. 修改建议（后续）

1. API 进程（SQLAlchemy 引擎）和命令行工具（一致性检查、实验）连接数据库时也没有超时，`/health` 在数据库主机不可达时会卡住。这次只做了清单里的 Worker；如有需要另立任务，在 `make_engine` 里加 `connect_args`。
2. OCR Worker 先加载模型（最长 `OCR_WORKER_LOAD_TIMEOUT_SECONDS`）、后检查数据库。数据库有问题时要等模型加载完才报错；调换顺序要改启动流程，没有在本任务里做。
