## 1. 问题（都在 main 的代码上核对过）

| 编号 | 问题 | 位置 |
|---|---|---|
| A3 | 注册成功、随后自动登录失败（网络抖动、数据库短暂不可用）时，页面仍停在“注册”模式，再点一次只会得到“用户名已存在”，用户不知道账号其实已经建好；而且注册一成功就提示“已自动登录”，登录失败时这句提示是错的 | `LoginView.vue` 的 `onSubmit` |
| B1 | 表单规则、提交流程、跳转都写在 `LoginView.vue` 里，没有一项自动化测试（项目没有组件测试工具） | `LoginView.vue` |
| C4 | 卡片标题“登录 / 注册新用户”是普通文字，读屏软件按标题跳转时找不到表单 | `el-card` 的 header |
| — | 表单校验是异步的，校验结束前“登录”按钮还没变成加载中，连按两次回车会发两次登录请求（注册模式下第二次得到“用户名已存在”） | `onSubmit` |
| — | 点“没有账号？注册”切到注册模式时，空表单立刻冒出“请输入用户名”“请输入密码”两行红字（本次在浏览器里发现，原来就有） | `el-form` 的 `rules` 一换，Element Plus 默认把整个表单校验一遍 |
| — | 注册密码长度用 Element Plus 的 `min` / `max`，按 UTF-16 长度算；后端按字符数（Python 的 `len`）算，含 emoji 的密码前后端判断不一致 | `registerRules` |

## 2. 修改

| 文件 | 修改 | 原因与影响 |
|---|---|---|
| `frontend/src/features/login/rules.ts`（新增） | 检查写成返回错误文字的纯函数：`requireUsername`、`requirePassword`、`checkNewUsername`、`checkNewPassword`；`LOGIN_RULES`、`REGISTER_RULES` 把它们包成 Element Plus 的 validator；提示文字集中在 `RULE_TEXT` | 测试测到的就是页面实际用的判断。提示文字与原来逐字相同。密码按字符数计算（修上表最后一行）。分支上提示文字随界面语言变化，main 没有中英文切换，改为中文常量 |
| `frontend/src/features/login/submit.ts`（新增） | `submitCredentials(mode, form, { register, login })` 返回三种结果之一：已登录、失败、已注册但登录失败；`singleFlight(task)`：上一次没结束时再调用直接返回 `null` | 请求函数由调用方传入，测试时换成假的。从分支原样移植，只改注释 |
| `frontend/src/features/login/LoginForm.vue`（新增） | 表单、模式切换、提交。登录成功后调用父组件传入的 `afterSignIn`（跳转）；“已注册但登录失败”时切回登录模式、保留用户名和密码，并提示“账号已创建，但自动登录没有成功（原因）。已切换到登录，请再点一次“登录”。”；“注册成功，已自动登录”改为登录成功后才提示；卡片标题改为 `h2`（`font: inherit`、`margin: 0`，外观不变）；表单加 `:validate-on-rule-change="false"` | 修 A3、C4、连续提交、切换模式冒红字。出错提示仍是顶部的 `ElMessage`（T24y 再改） |
| `frontend/src/features/login/LoginBrand.vue`（新增） | 系统标志、系统名、说明，样式从原 `LoginView.vue` 原样搬来 | 分支上的品牌区有 logo 插槽（给星尘光球用）；main 没有别处会传 logo，不加插槽（GLOBAL §8.1 不写没有用途的接口） |
| `frontend/src/views/LoginView.vue` | 只留布局：`<LoginBrand />` + `<LoginForm :after-sign-in="goBack" />`，`goBack` 用 T24v 的 `safeRedirect` | 从 154 行减到 36 行 |
| `frontend/tests/login/rules.test.ts`（新增，26 项） | 用户名 2 / 3 / 32 / 33 个字符、中文、空格、`@`、斜杠；密码 7 / 8 / 128 / 129 个字符、中文和空格、emoji 按 1 个字符；登录时只检查填了没有；四条规则都是必填、失去焦点时检查；调用 validator 的结果；提示文字与拆分前相同 | 从分支移植。去掉了“切换语言”那 1 项，换成“提示文字与拆分前相同” |
| `frontend/tests/login/submit.test.ts`（新增，8 项） | 登录成功；密码错误；注册后登录成功；注册返回 409；注册成功但登录失败；提交过程中重复调用只执行一次；结束后可以再次提交；上一次抛出异常后也能再次提交，异常原样抛给调用方 | 从分支原样移植 |

## 3. 验证

- `npm run typecheck` 通过；`npm test` 13 个文件 165 项通过（新增 34 项）；`npm run build` 成功（登录页 chunk 4.11 KB，gzip 2.05 KB）。
- 浏览器检查（开发服务器 + 临时模拟后端，同 T24v）：
  - 1280×800 下拆分前后量了 9 个元素（标志、标题、说明、卡片、卡片标题、两个输入框、按钮、切换链接）的位置和大小，完全相同；卡片标题现在是 `H2`，字号 16 px、字重 400，与原来相同；
  - 拆分前点“没有账号？注册”冒出两行红字（截图确认），拆分后切换不再冒红字；
  - 让模拟后端在注册后的第一次登录返回 503：页面切回“登录”，用户名和密码保留，顶部提示“账号已创建，但自动登录没有成功（数据库不可用，请稍后重试）……”；再点“登录”进入文件页；
  - 模拟后端登录接口延迟 1.5 秒，在密码框里连按两次回车：模拟后端只收到一次登录请求；
  - 密码错误：顶部提示“用户名或密码错误”，停在登录页。
- **未测试（Not Tested）**：与真实后端联调（注册、注册后自动登录、409、422 的真实应答），本机没有 PostgreSQL。已登记到 `docs/untested.md`。
