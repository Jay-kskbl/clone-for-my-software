## 1. 问题

`GET /api/documents/{id}/text` 按 `seq` 排序。OCR 片段的 `seq` 从 10 亿开始（D30），所以一份混合 PDF（第 1、3 页有文字层，第 2、4 页是扫描件）返回的顺序是：

```text
修改前：第1页正文 → 第3页正文 → 第2页OCR → 第4页OCR
修改后：第1页正文 → 第2页OCR → 第3页正文 → 第3页OCR → 第4页OCR
```

### 2.1 `backend/app/api/document_text.py`（+19/−9 行）

| # | 位置 | 修改前 | 修改后 | 原因 |
|---|---|---|---|---|
| 1 | 模块说明 | 两段 | 加一段：排序规则、为什么要改、没有页码的定位怎么处理 | — |
| 2 | import | `func, select` | `Integer, case, func, select, tuple_` | 排序表达式和行比较 |
| 3 | 新增模块常量 | — | `_PAGE_KEY = coalesce((locator->>'page')::int, 0)`；`_SOURCE_KEY = CASE WHEN source_type='body' THEN 0 ELSE 1 END`；`_PREVIEW_ORDER = (_PAGE_KEY, _SOURCE_KEY, seq)` | 列表和跳转共用同一组排序键 |
| 4 | `_page_containing()` 的存在性检查 | `count(*) … WHERE chunk_id = ?`，有就继续 | `SELECT 三个排序键 … WHERE chunk_id = ?`，取不到返回第 1 页 | 下一步要用目标的三个键 |
| 5 | `_page_containing()` 的计数 | `count(*) WHERE seq < 目标 seq` | `count(*) WHERE (k1, k2, k3) < (目标的 k1, k2, k3)` | 必须和列表用同一顺序，否则跳到的页里没有目标片段 |
| 6 | 列表查询 | `.order_by(DocumentChunk.seq)` | `.order_by(*_PREVIEW_ORDER)` | 核心改动 |

没有页码的定位（`docx_para`、`xlsx_range`、`image`）页码按 0 算，同一文档里来源类型也只有一种（Word、Excel 只有 body，图片只有 ocr），所以这几类文档的顺序和修改前完全相同。权限检查、只看当前版本、`source_type` 过滤、分页参数都没有改。

2. **补测时一起跑。** `test_document_text.py` 的 21 项（原有 11 + 新增 10）要在有 PostgreSQL 的机器上一起重跑。
3. **以后有内嵌图片（P4）时。** 同一页会同时有正文和 OCR，现在的规则是正文在前。如果实际看起来不合适（例如图片在页面中间），可以再按 bbox 细排，现在不需要。
