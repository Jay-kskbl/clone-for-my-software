### 与原来行为的差别

- 跳转：`/\evil.com`、带控制字符的地址、`/login` 原来会原样交给 `router.push`，现在回到 `/`。其余与原来相同
- 注册密码长度：原来由 Element Plus（async-validator）计数，现在按字符数（`[...value].length`）计数，与后端 Python 的 `len` 一致。普通字符没有差别
- 提示文字的位置、样式、触发时机（失去焦点、点提交）不变

### 与计划的差别

计划写的是 L1 同时新增 `errors.ts`，“先只放现有行为”。那样它只是把 `errorMessage` 原样转一手，是一个没有实际用途的空模块（GLOBAL §8.1），所以挪到 L6 和错误码翻译一起新增。

## L2 后端连不上时保留令牌（修 A1）

### 修改的文件

| 文件 | 改了什么 | 为什么 |
|---|---|---|
| `frontend/src/auth.ts` | `restoreSession` 只在后端明确拒绝（401 或其他 4xx）时删除令牌；网络不通（status 0）和 5xx（开发代理的 502、数据库不可用的 503、500）时保留令牌、`ready` 保持 `false`，并把新字段 `unreachable` 置为 `true`。`login`、`logout` 和成功确认时清掉 `unreachable` | 原来任何失败都删令牌，后端重启、网络短暂断开时用户一刷新就被退出（问题 A1） |
| `frontend/src/views/LoginView.vue` | `auth.unreachable` 时在卡片里表单上方显示黄色提示（`el-alert`，已注册的组件）和“重试”按钮；点重试重新确认，成功就直接跳到 `redirect`，不用再输密码 | 让用户知道登录状态还在、该怎么办 |
| `frontend/src/i18n/messages.ts` | `login.unreachable`、`login.retry` 中英文各一条 | — |
| `frontend/tests/auth.test.ts`（新增） | 12 项：没有令牌不发请求；令牌有效；确认一次后不再请求；401 删令牌；网络不通、502、503、500 保留令牌并标记；恢复后再确认即登录；恢复后令牌已过期则删除；连不上之后登录成功、退出登录都清掉标记 | 原来 `auth.ts` 没有测试 |

路由守卫没有改：连不上时 `auth.user` 为空，需要登录的页面照旧跳到登录页并带上 `redirect`。

### 验证

- `npm run typecheck` 通过；`npm test` 19 个文件 206 项通过（新增 12 项）
- 浏览器（开发服务器，没有后端，开发代理对 `/api` 返回 502）：在本地写一个假令牌后打开 `/search?q=合同` → 跳到 `/login?redirect=…`，卡片里出现黄色提示，本地令牌仍在；点“重试”又发了一次 `/api/auth/me`，提示仍在，令牌仍在。测完删掉了假令牌
- 服务恢复后点“重试”直接进入原页面：浏览器里**未测试（Not Tested）**（需要后端），由单元测试“连不上之后服务恢复”覆盖逻辑，`onRetry` 已做代码复核

### 注意

- 连不上时，打开一个需要登录的页面会请求两次 `/api/auth/me`：一次在原页面的导航，一次在跳到登录页的导航（`ready` 为 `false`，每次导航都再确认）。只在连不上时发生，没有处理
- 后端长时间不在时令牌一直留在本机；令牌 1 小时后过期，下次连上时会收到 401 并删除
