写步骤时核对过的代码事实（都是读代码得到的，没有在本机运行）：

- 两个 Worker 的提示文字取自 `backend/app/worker/__main__.py`、`schema.py` 和 `services/ocr_worker/ocr_worker/__main__.py`。OCR Worker 先加载模型、再连数据库，所以 11.5 节用两种超时设置的耗时差来判断设置有没有生效。空库上 OCR Worker 缺的列数是 34，由 `REQUIRED_COLUMNS` 四张表的列数相加（7 + 7 + 7 + 13）。
- 一致性检查在库里没有图片向量时，不把“向量索引不存在”算作问题；`rebuild_indices()` 会把三个索引一起建出来；提示里的索引名不带前缀。
- `search_analyzer` 可以用 mapping 接口直接更新到已有字段上（要同时写上原来的 `type` 和 `analyzer`），所以 11.3 节办法 A 不用删索引。OpenSearch 万一拒绝，用办法 B（加一个多出的字段）。
- Vite 8.3.8 的 `resolvePreviewOptions` 里 `proxy: preview?.proxy ?? server.proxy`，所以 `npm run preview` 也会转发 `/api`、`/health`。11.6 节仍要求执行时用网络面板确认一次。
- `git diff` 在 `autocrlf=true` 时会把 CRLF 当成 LF 来比较，看不出差别，所以 11.2 节用 `git ls-files --eol`。临时处理推荐 `core.autocrlf input`，不用 `false`：用 `false` 的话，在 Windows 上编辑并提交的 CRLF 文件会原样进入仓库。
