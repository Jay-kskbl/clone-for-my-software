## 1. 问题

| 参数 | 作用 | 修改前的问题 |
|---|---|---|
| `OCR_PDF_DPI`（默认 200） | 扫描页渲染成图片的分辨率，直接决定识别出什么字 | 只在 OCR Worker 的环境变量里，backend 读不到，实验 `config.json` 没有记录（GLOBAL §8.2） |
| `OCR_MIN_CONFIDENCE`（默认 0.0） | 置信度低于它的行不进入 OCR 片段，也就检索不到 | 同上 |
| `OCR_MAX_PIXELS` | 图片像素上限，超过就拒绝识别 | 同上 |

另外，改了配置只影响之后识别的页，库里新旧结果混在一起时发现不了，B2、B3 的数字就无法复现。

## 4. 修改建议（后续）

1. **补测时先迁移。** 下次在有 PostgreSQL 的机器上补测，要先 `alembic upgrade head`（到 0002），再跑 `test_migrations.py`、`test_ocr_worker_db.py`、`test_experiments_db.py`。正式实验库也要先升级，否则 OCR Worker 写入时会报“列 params 不存在”。
2. **烟测脚本加一项检查。** `scripts/smoke/ocr_e2e.py` 可以在 OCR 完成后查一次 `ocr_results.params` 是否有值，这样一次烟测就能覆盖真实写入。这次没改，因为这个脚本刚入库、还没在本仓库上跑过。
3. **“重新 OCR”的入口。** 现在参数不一致只能整库重来。如果阶段五需要比较不同 DPI 或置信度阈值（这本身可能是个有价值的实验），需要一个“对指定文档重新建 OCR 任务”的命令。另外，`min_confidence` 是在切分时过滤的、`lines` 保存了全部行，所以只改阈值时可以不重新识别、只重新切分。两者都超出 T24c 的范围，记作待议，需要 Barry 决定。
4. **OCR 模型的检查。** 快照记录了 `ocr_models`，但运行前检查没有拦“数据集里用了两个不同的 OCR 模型”。和参数不一致是同一类问题，可以用同样的办法补上，记作待议。
