## 1. 问题

T10、T16、T23 的页面是逐个任务加出来的，问题有：

- 顶栏布局，内容区没有最大宽度，宽屏上表格和结果拉得很长；颜色在各组件里写死十六进制值，同一种灰色写了好几处。
- 文件页上传只弹 toast，一次选多个文件时看不出哪个成功、哪个失败；列表加载失败弹消息，自动刷新失败完全不提示，列表会悄悄停在旧状态（GLOBAL §12“不要将错误静默转换成空结果”）。
- 检索页看不出“多通道检索 + RRF 融合”：开关只有“正文 / OCR”两个勾选框和一个“图像语义检索”勾选框，结果上只有命中通道的标签，RRF 融合分（`hit.score`）没有显示；关掉某个通道做对照时要手动再点一次检索。
- 文件列表和预览页各写了一份“取回 Blob 再保存”的下载代码。
- 预览页直接打开链接（没有上一页）时，“← 返回”会离开本系统。

## 3. 取舍

1. **上传进度用“逐个文件的状态”代替百分比进度条。** 现有请求用 fetch，拿不到上传进度；要显示百分比得改用 XHR，而本机上传几乎瞬间完成。百分比进度列为后续建议。
2. **融合分的提示不写死 k=60。** k 是后端配置（`search_rrf_k`），接口不返回 k 的值，写死在前端会和配置不一致。
3. **图标手画 SVG**，没装 @element-plus/icons-vue（不新增依赖）。
4. **主题色保持 Element Plus 默认蓝**，只把散落的色值统一成变量。

## 6. 修改建议（后续）

1. **上传百分比进度**：要显示百分比，上传请求得从 fetch 改成 XHR（`upload.onprogress`）。本机上传几乎瞬间完成，部署到网络较慢的环境、上传接近 50 MB 的文件时再考虑。
2. **真实后端联调时核对检索页和 `/health`**：`HealthResponse` 的字段、`clip_service.status` 的取值、检索响应 `channels` 里各通道的 `status` 和 `took_ms`、降级时图像格显示“不可用”；顺带看一次侧栏的管理员标签和“管理员可见”来源（`untested.md` §4“管理员视角的前端”）。
3. **图片预览缩放**：预览页的图片按容器宽度缩小显示（`max-width: 100%`），不能放大看细节；PDF 有 50%–300% 缩放，图片没有。属于新功能，需要 Barry 决定。
4. **检索结果没有分页**：检索请求不传 `top_k`，用后端默认的 `SEARCH_DEFAULT_TOP_K`（20），一次最多显示 20 个文件。要看更多结果需要分页或“加载更多”（`top_k` 上限 `SEARCH_MAX_TOP_K` 默认 100，api.md §7.1），需要 Barry 决定。
5. **界面截图要在 T31 前重截**：T24s 改了全部页面的布局和配色，`frontend/README.md`、用户手册、论文里如果用了之前的界面截图（包括 `docs/screenshots/windows-2026-11-19/` 里的 5 张），要在 T31 一致性核对前按新界面重截（GLOBAL §13“系统功能、论文描述、截图和答辩演示必须一致”）。
