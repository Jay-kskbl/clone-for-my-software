## 1. 问题（A1，在 main 的代码上核对过）

`auth.ts` 的 `restoreSession` 在页面加载时用本地令牌请求 `GET /api/auth/me`，任何失败都删令牌（注释原文：“令牌过期、账号被删或后端不可用：都按未登录处理”）。后端重启、开发代理返回 502、数据库不可用返回 503、网络短暂断开时，用户一刷新页面就被退出，服务恢复后还要重新输入密码。只有 401 才说明令牌真的失效。

## 2. 修改

| 文件 | 修改 | 原因与影响 |
|---|---|---|
| `frontend/src/auth.ts` | 新增 `cannotConfirm(error)`：`ApiError` 且 `status === 0`（网络不通）或 `>= 500`。`restoreSession`：没有令牌时直接确认完毕；`fetchMe` 失败且 `cannotConfirm` 时保留令牌、`user = null`、`unreachable = true`、`ready` 不置位后返回；其余失败（401 等）与原来相同，删令牌。状态新增 `unreachable`，`login`、`logout` 都把它清掉 | 修 A1。`ready` 不置位，之后每次导航都会重新确认；理由与代价见 D51。从分支原样移植，只改注释 |
| `frontend/src/features/login/LoginForm.vue` | 卡片标题下、表单上方加默认插槽 | 页面用它放提示 |
| `frontend/src/views/LoginView.vue` | `auth.unreachable` 时在插槽里显示警告“暂时连不上服务器，登录状态已保留。服务恢复后点“重试”即可继续。”和“重试”按钮；重试调用 `restoreSession()`，确认成功就按 `redirect` 回原页面 | 需要登录的页面仍然跳登录页（带 `redirect`），用户知道发生了什么，服务恢复后不用再输密码 |
| `frontend/tests/auth.test.ts`（新增，12 项） | 用假的 `fetch` 和 `localStorage`：没有令牌；令牌有效；401 删令牌；网络不通、502（开发代理）、503（数据库不可用）、500 保留令牌并标记 `unreachable`；服务恢复后再次确认就登录；恢复后令牌已过期则删除；确认过一次之后不再请求；连不上之后登录成功、退出登录都清掉 `unreachable` | 从分支原样移植，只改了文件头注释 |

## 3. 验证

- `npm run typecheck` 通过；`npm test` 14 个文件 177 项通过（新增 12 项）；`npm run build` 成功。
- 浏览器检查（开发服务器 + 临时模拟后端）：
  - 登录后**真正停掉模拟后端**（Vite 开发代理对 `/api/auth/me` 返回 502），打开 `/search?q=abc`：跳到 `/login?redirect=/search?q=abc`，本地令牌**仍在**，卡片上方显示“暂时连不上服务器，登录状态已保留……”和“重试”（原来这里令牌会被删掉）；
  - 重新启动模拟后端（它的令牌存在内存里，重启后全部失效），点“重试”：收到 401，令牌被删，提示消失，停在登录页，`redirect` 保留；
  - 重新登录后，让模拟后端对所有接口返回 502（模拟后端没启动），再打开 `/search?q=abc`：同样跳登录页、保留令牌、显示提示；恢复模拟后端后点“重试”：直接回到 `/search?q=abc`，检索框里是 abc，不用再输密码。
