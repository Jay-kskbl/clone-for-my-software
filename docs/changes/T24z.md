## 1. 问题（C5）

登录页不知道后端是否在线：要填完表单、点了“登录”才看到“服务暂时不可用（HTTP 502）”。演示前不容易发现后端或数据库没启动。

## 2. 修改

| 文件 | 修改 | 原因与影响 |
|---|---|---|
| `frontend/src/features/login/serviceStatus.ts`（新增） | `checkLoginService(load)` 返回四种状态之一：`ok`；`backend-down`（`NETWORK` 或 `UNAVAILABLE`，即网络不通或开发代理 502–504）；`database-down`（`/health` 里 `database.status === 'unavailable'`）；`unknown`（应答格式不对等，不提示，免得说错）。本函数不抛异常 | 登录只需要后端和数据库，OpenSearch、CLIP 服务不可用不影响登录，不看（检索页自己会提示）。`load` 由调用方传入（页面传 `api/health.ts` 的 `fetchHealth`），测试时换成假的。从分支原样移植，只改注释 |
| `frontend/src/views/LoginView.vue` | 挂载后调用一次 `GET /health`（`singleFlight` 防止重复）；`backend-down` 时提示“连不上后端服务，现在无法登录。请确认后端已启动，再点“重新检查”。”，`database-down` 时提示“后端已启动，但数据库不可用……”，都带“重新检查”按钮；不轮询；检查完成之前按正常处理，不显示提示。与 T24x 的“登录状态已保留”同时成立时只显示 T24x 那一条（它的“重试”没进去时也会顺便重新检查服务状态） | 修 C5。每次打开登录页多一次 `/health` 请求；`/health` 是公开接口，T24b 起只返回状态和异常类型，不暴露主机和端口 |
| `frontend/tests/login/service-status.test.ts`（新增，16 项） | 数据库正常 / 不可用；OpenSearch、CLIP 不可用不影响登录；网络不通、502、503、504 判为后端连不上；其他接口错误、应答格式不对判为 `unknown`；`fetchHealth` 经假的 `fetch` 走一遍完整链路 | 从分支原样移植，只改了文件头注释 |

## 3. 验证

- `npm run typecheck` 通过；`npm test` 16 个文件 205 项通过（新增 16 项）；`npm run build` 成功（登录页 chunk 6.55 KB，gzip 3.04 KB）。
- 浏览器检查（开发服务器 + 临时模拟后端，1280×800）：
  - 模拟后端正常：打开 `/login` 没有提示；
  - 模拟后端报告数据库不可用：打开 `/login` 显示“后端已启动，但数据库不可用……”和“重新检查”；恢复数据库后点“重新检查”，提示消失；
  - 登录后**真正停掉模拟后端**，打开 `/search`：跳到登录页，只显示 T24x 的“登录状态已保留”一条（服务状态检查此时也判为连不上，但不重复显示）；
  - 清掉令牌后打开 `/login`：显示“连不上后端服务，现在无法登录……”；重新启动模拟后端后点“重新检查”，提示消失。
- **未测试（Not Tested）**：对着真实后端的 `/health`。数据库直接拒绝连接时 `/health` 应当很快返回；数据库主机连不上（不应答）时要等连接超时（`health_check_timeout_seconds`）才返回，提示会晚一点出现。两种情况的实际耗时都没有测。已登记到 `docs/untested.md`。
