## 1. 问题（都在 main 的代码上核对过）

| 编号 | 问题 | 位置 |
|---|---|---|
| A2 | 使用中令牌过期，任一请求收到 401 `UNAUTHENTICATED` 后跳回登录页时不带原地址，重新登录后到文件页，检索词和预览位置丢失 | `main.ts` 的失效回调 `router.push({ name: 'login' })` |
| A4 | 已登录时打开 `/login?redirect=/search`，被送到文件页而不是 `/search`（多开标签页时会遇到） | `router.ts` 守卫 `return { name: 'documents' }` |
| B2 | 登录后跳转地址只检查“以 `/` 开头、不以 `//` 开头”，没有测试；`/\evil.com`（浏览器把反斜杠当斜杠）、带换行或制表符的地址没处理 | `LoginView.vue` 的 `onSubmit` |

B2 的后果：`router.push` 只在站内跳转，跳不出站点；但不合格的地址可能让登录成功后报“发生了未预期的错误”、停在登录页。

## 2. 修改

| 文件 | 修改 | 原因与影响 |
|---|---|---|
| `frontend/src/features/login/redirect.ts`（新增） | 4 个纯函数：<br>• `safeRedirect(raw)`：只接受以单个 `/` 开头的站内路径；含反斜杠、控制字符（`\u0000`–`\u001f`、`\u007f`），以 `//` 开头，带协议，空值、数组、非字符串，以及 `/login` 本身，一律回到 `/`；<br>• `loginRoute(fullPath)`：去登录页并带上原地址，原地址是首页、登录页或不合格时不带；<br>• `guardTarget(to, signedIn)`：路由守卫的决定；<br>• `afterUnauthenticated(wasSignedIn, current)`：收到 401 后去哪里 | 规则集中一处，可以单元测试。从分支原样移植，只改了注释（分支注释里的问题编号指向一份 main 上没有的计划书） |
| `frontend/src/router.ts` | 守卫改为 `return guardTarget(to, auth.user !== null)` | 未登录访问需要登录的页面：行为与原来相同（带 `redirect`，首页不带）；已登录访问登录页：按 `redirect` 返回（修 A4） |
| `frontend/src/main.ts` | 失效回调先算 `afterUnauthenticated(auth.user !== null, 当前路由)`，再 `logout()`，有目标才跳 | 使用中过期的带上当前地址（修 A2）。原来就没登录（页面加载时 `restoreSession` 确认令牌收到 401）时不再跳：此时导航还没完成，当前路由是起始位置 `/`，路由守卫马上会带着目标地址跳到登录页，这里再跳一次是多余的导航，结果还取决于两次导航的先后 |
| `frontend/src/views/LoginView.vue` | 登录成功后 `router.push(safeRedirect(route.query.redirect))` | 修 B2；页面其余部分不变（T24w 再拆分） |
| `frontend/tests/login/redirect.test.ts`（新增，38 项） | 站内路径原样保留（含中文检索词、锚点、`/loginhelp`）；14 种不合格地址回首页（`//evil.com`、`/\evil.com`、`https://…`、`javascript:`、制表符、换行、DEL、`/login` 及其带参数和锚点的形式等）；非字符串；`loginRoute`；`guardTarget` 6 种情况；`afterUnauthenticated` 4 种情况 | 从分支移植。原来有一项用分支上的演示页 `/motion-lab` 当“公开页面”，main 上没有这个路由，改成一个不需要登录的虚构页面，判断内容不变 |
