## 1. 问题

`python -m app.modules.consistency repair --fix rebuild-indices` 只在检查发现 `index_missing` 或 `index_structure_mismatch` 时才重建。结构检查只比较字段类型、分词器类型和 BM25 参数。如果改了检查比较不到的设置（例如 `search_analyzer`、分析器内部参数），命令会回答“所选类别下没有需要修复的问题”，只能手动去 OpenSearch 删索引。

## 4. 修改建议（后续）

1. **CLAUDE.md。** “一致性检查”一条写了 `--fix rebuild-indices`，没有提 `--force`。以前改 CLAUDE.md 都先问过 Barry，这次没改，**需要 Barry 同意后补一句**，例如“检查没发现问题也要重建时加 `--force`（仍需 `--yes`）”。
2. **扩大结构检查的比较范围。** 根本办法是让检查能发现 `search_analyzer` 之类的差异，这样不需要 `--force` 也会提示重建。但这会改变检查结果，可能对现有索引报出新的不一致，影响面比 `--force` 大，记作待议。
3. **阶段五换分词设置时的顺序。** 先停两个 Worker → 改 mapping 文件 → `repair --fix rebuild-indices --force` 演练确认 → 加 `--yes` 执行 → `check` 确认没有问题 → 实验配置里会自动记下新的 mapping hash（`code_versions`）。建议写进 T30 的部署说明。
4. **`parser.error` 打印的 usage 是总命令的。** 现在错误信息上面一行是 `usage: python -m app.modules.consistency [-h] {check,repair} ...`，不是 `repair` 子命令的用法。不影响使用，如果想更准确，可以改用 `repair` 子解析器的 `error()`。
