## 1. 问题

`main.ts` 用 `app.use(ElementPlus)` 和 `element-plus/dist/index.css` 整包引入 Element Plus。页面实际只用 23 个组件，主包却有约 874 KB（CSS 约 363 KB），生产构建时 Vite 提示超过 500 KB（D22 当时认为可以接受）。

## 2. 逐文件修改记录

| 文件 | 修改 | 原因 |
|---|---|---|
| `frontend/src/element-components.ts`（新增，65 行） | `ELEMENT_COMPONENTS`：页面用到的 23 个组件；`componentName()`：取组件的注册名 | 单独成文件、不引入样式，测试才能在 Node 里导入（Node 不认识 .css） |
| `frontend/src/element.ts`（新增，52 行） | 26 个按组件引入的样式（23 个组件，加上 `v-loading`、ElMessage、ElMessageBox）；`installElementPlus(app)`：逐个 `app.component(名字, 组件)`，注册 `ElLoading` 指令，`app.use(ElMessage)`、`app.use(ElMessageBox)`（让脚本里调用的消息框拿到应用上下文），`provideGlobalConfig({ locale: zhCn }, app, true)`（等同于原来整包安装时的中文全局配置） | — |
| `frontend/src/main.ts`（+5/−5 行） | 去掉整包的 import 和 CSS，改为 `installElementPlus(app)` | — |
| `frontend/tests/element.test.ts`（新增，3 项） | 用 `import.meta.glob` 读出全部 `.vue` 的源码，找出所有 `<el-xxx>`，逐个核对已注册；注册名以 El 开头且不重复 | 漏注册的组件在 Vue 里只是一条控制台警告、页面上不显示，必须有测试兜住 |

**为什么用 `app.component` 逐个按名字注册，而不是 `app.use`。** 浏览器检查时发现：ElRadioGroup、ElRadioButton 这类子组件自己的 `install` 什么都不做，要靠父组件 ElRadio 的 `install` 才注册上。第一版用 `app.use` 且清单里没有 ElRadio，文件列表上方的“全部 / 我上传的 / 共享给我的”就没显示，而测试按名字核对照样通过。改成按名字直接注册后，测试核对的名字就是实际注册的名字，这种情况不会再漏。

## 3. 效果（生产构建）

| 产物 | 改动前 | 改动后 |
|---|---|---|
| 主 JS（`index-*.js`） | 873.8 KB | 348.9 KB |
| 公共 JS（`client-*.js`，登录页起就要加载） | — | 82.6 KB |
| 消息框 JS（`message-*.js`，用到 ElMessage 的页面加载） | — | 51.4 KB |
| 主 CSS（`index-*.css`） | 362.6 KB | 149.5 KB |

首屏需要的 JS 合计约 483 KB（原来约 874 KB），减少约 45%；CSS 减少约 59%。`pdf.worker`（1.27 MB）和预览页（约 452 KB，含 pdf.js）本来就是单独按需加载的，没有变。

## 5. 修改建议（后续）

1. 以后新页面用到新的 Element Plus 组件，要在 `element.ts` 加样式、在 `element-components.ts` 加 import 和清单项；漏了 `npm test` 会失败。
2. 标签（ElTag）首次出现时有一段 Element Plus 自带的入场动画，截图太快会拍到空白；这是组件原有行为，改动前后一样。
